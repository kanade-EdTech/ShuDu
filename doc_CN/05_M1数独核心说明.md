# 虚拟歌手数独——M1 数独核心说明

> 版本：0.2.0-m1  
> 完成日期：2026-10-04  
> 状态：M1 已完成；Chrome 61、平台模拟器与真机仍未实测

## 1. 完成范围

M1 已将静态界面升级为可操作的数独试玩版本：

- 4×4 与 9×9 棋盘模型。
- 题面和答案结构校验。
- 行、列、宫关联格计算。
- 选格、角色填入、替换和清除。
- 最多 100 步的棋盘撤销历史。
- 即时冲突识别与界面标红。
- 正确完成判断与完成提示。
- 简易/高难模式切换，两个模式的内存状态互不覆盖。
- 鼠标、触摸点击和基础键盘操作。

M1 不包含随机题库、自动存档、头像上传、BGM 或计时逻辑；这些仍按 M2–M4 实施。

## 2. 文件职责

| 文件 | 职责 |
| --- | --- |
| `domain.js` | 纯数值领域模型、规则校验、冲突、完成判断和 reducer |
| `app.js` | DOM 渲染、事件绑定、模式协调和界面状态 |
| `index.html` | 4×4/9×9 单页结构及本地经典脚本加载顺序 |
| `style.css` | 选中、关联、玩家填入、冲突、完成及禁用状态 |
| `tests/domain.test.mjs` | 数独核心单元测试 |
| `scripts/browser-smoke.mjs` | 构建产物的真实 Chrome 交互链测试 |

领域层不知道角色名称、图片路径或 DOM，只处理 `0..size` 数值。角色图片仍由 `.char-1` 至 `.char-9` 映射，因此更换素材不会改变棋盘答案。

## 3. 数据与动作

### 3.1 Puzzle

- 仅接受 4×4 或 9×9。
- `givens` 与 `solution` 长度必须为 16 或 81。
- `givens` 的非零值必须与答案同位置一致。
- `solution` 的每行、每列和每宫必须完整包含 `1..size`。

### 3.2 GameState

当前内存状态包含：模式、题目 ID、棋盘数值、选中位置、撤销历史、游戏状态和有效棋盘变化步数。

### 3.3 Action

| Action | 结果 | 写入撤销历史 |
| --- | --- | ---: |
| `SELECT_CELL` | 切换当前格 | 否 |
| `PLACE_VALUE` | 在非预置格填入或替换角色 | 是 |
| `CLEAR_CELL` | 清空当前玩家格 | 是 |
| `UNDO` | 恢复上一次棋盘内容 | 消费一项 |
| `NEW_GAME` | 重置当前基准题 | 清空 |

预置格不允许修改。无效位置、超出范围的数值和重复填入相同数值不会产生历史记录。

## 4. 冲突与完成规则

填入动作不会被冲突预先拦截。系统接受本次填入，并同时标记所有发生重复的相关格，便于用户理解错误位置。

只有同时满足以下条件才进入 `completed`：

1. 棋盘没有空格。
2. 没有同行、同列或同宫冲突。
3. 每一格与题目的唯一解完全一致。

撤销完成前最后一步后，状态立即回到 `playing`。

## 5. 当前交互

- 点击棋盘格：选中格子并高亮同行、同列、同宫。
- 点击角色按钮：选择该数值，并填入当前非预置格。
- 清除：清空当前玩家格。
- 撤销：恢复上一步棋盘内容。
- 新一局：重置当前模式的固定基准题。
- 数字键 `1–4` 或 `1–9`：填入对应角色。
- `Backspace` / `Delete`：清除当前玩家格。
- `Ctrl/Cmd + Z`：撤销。
- 底部模式开关：在两份独立内存棋局之间切换。

头像管理、暂停和音乐按钮在 M1 中明确禁用，避免把尚未实现的视觉按钮误认为可用功能。

## 6. 临时基准题

M1 内置一题 4×4 和一题 9×9，只用于玩法与测试闭环。M2 将：

- 生成并验证正式 4×4 唯一解题库。
- 从原始 9×9 数据集中抽样、去重和验证。
- 引入洗牌袋与最近题目避重。
- 用正式题库替换 `app.js` 中的固定题面。
