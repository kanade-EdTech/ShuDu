# 虚拟歌手数独——开发计划

> 文档版本：v0.1  
> 计划状态：执行中（M0–M5 本地开发与验证已完成，平台容器与真机待 M6 验收）  
> 最后更新：2026-10-11  
> 对应范围：首发 P0，支持 B站 Toy 与小红书小工具

## 1. 计划目标

在现有静态界面稿基础上，完成一款可离线运行、可恢复进度、可替换角色头像并支持 BGM 的虚拟歌手数独。首发同时提供：

- 4×4 简易模式，固定使用文件名以 1–4 开头的默认角色素材。
- 9×9 高难模式，使用文件名以 1–9 开头的默认角色素材。
- 标准数独规则、撤销、清除、冲突提示、完成判断与重新开局。
- 简易和高难模式各自独立的未完成棋局存档。
- 4 人版和 9 人版角色头像自定义、裁切、排序及恢复默认。
- 内置 BGM 的播放、暂停、切歌和音量记忆。
- B站 Toy 与小红书小工具两套合规的离线发布产物。

本计划只覆盖 P0。候选笔记、提示、每日挑战、成绩统计、排行榜和云同步进入 P1 或以后版本。

## 2. 当前基线

进度记录：2026-10-03 已完成 M0 开发基线，建立外置 CSS/经典脚本、零依赖双平台构建、静态门禁和冒烟测试。2026-10-04 已完成 M1 数独核心，实现 4×4/9×9 棋盘模型、规则校验、填入、清除、撤销、冲突显示、模式切换与完成判断。同日完成 M2：接入 100 道 4×4 题；把 Sudoku Exchange 的四个源文件作为四个独立难度库，各固定种子抽取 1,000 道，共 4,000 道 9×9 题；全部经独立唯一解复核，并以紧凑格式发布，实现各库独立洗牌与最近 20 题避重。M3 也已完成：简易与高难棋局分别自动保存，刷新可恢复题目、难度、盘面、选格、步数与撤销历史；损坏或不可用存储会安全降级。Chrome 61、平台模拟器与真机兼容性仍待 M5–M6 验证。

## 3. 计划假设

- 基准人力：1 名前端开发为主，设计确认、素材授权和真机验收由项目负责人配合。
- 基准周期：约 5–6 周；若只有零散开发时间，应按阶段顺延，不压缩测试与发布门禁。
- 技术方向：DOM/CSS + ES2017 兼容 JavaScript；不使用联网服务、WebGL、Worker 或 WASM。
- 首发优先稳定性和离线体积，不追求复杂动画或大型曲库。
- 小红书端不提供本地音频导入；B站 Toy 仅在能力验证通过后开放。

## 4. 里程碑总览

| 里程碑 | 建议周期 | 主要结果 | 退出条件 |
| --- | --- | --- | --- |
| M0 开发基线 | 1–2 天 | 工程结构、构建与测试骨架 | 本地可构建，静态页面无回归 |
| M1 数独核心 | 4–5 天 | 4×4/9×9 可完整游玩 | 规则、撤销、完成判断通过测试 |
| M2 题库与开局 | 3–4 天 | 两类离线题库与选题机制 | 所有发布题目均有唯一解 |
| M3 存档与模式 | 3–4 天 | 双模式自动保存、恢复与迁移 | 刷新、切换模式不丢局面 |
| M4 角色与 BGM | 5–7 天 | 头像管理、内置音乐、平台降级 | 重启后素材状态正确，失败可恢复 |
| M5 双平台适配 | 4–5 天 | Toy 与小红书独立产物 | 路径、CSP、体积和能力扫描通过 |
| M6 验收发布 | 3–5 天 | 回归、真机测试、发布说明 | P0 验收项全部关闭或有明确豁免 |

关键路径为：`M0 → M1 → M2 → M3 → M5 → M6`。M4 的素材准备可与 M2、M3 并行，但不能晚于 M5。

## 5. 分阶段实施计划

### 5.1 M0：建立开发基线

任务：

1. 将现有界面拆分为入口、样式、经典脚本和本地资源，保持 `index.html` 为发布根入口。
2. 确定构建目标为 ES2017 / Chrome 61，不输出 module、source map 或外部依赖。
3. 建立 `src`、`data`、`assets`、`scripts`、`tests`、`dist/toy`、`dist/xhs` 目录职责。
4. 建立格式检查、单元测试、生产构建和静态资源检查命令。
5. 记录首屏尺寸、静态包体和当前界面截图作为回归基线。

交付物：工程骨架、可重复构建命令、首版质量门禁。

验收标准：

- 开发版与生产版均可离线打开。
- 页面不依赖 CDN、外部字体或远程图片。
- 现有 4×4/9×9 视觉稿无明显布局回归。

### 5.2 M1：实现数独核心

任务：

1. 实现 `Board`、`Puzzle`、`GameState` 和动作模型。
2. 实现行、列、宫索引计算及冲突检测。
3. 实现选格、填入、替换、清除、撤销和重新开局。
4. 区分预置格、玩家格、当前格、关联格和冲突格。
5. 实现完成判断、暂停状态和基于时间戳的计时。
6. 用数值维护领域状态，再通过 `IconSet` 映射到角色图片。

交付物：不用存档也能完整游玩的 4×4 与 9×9 页面。

验收标准：

- 预置格不可修改。
- 同行、同列、同宫重复值能被正确识别。
- 撤销只回退棋盘变化，不破坏选择状态。
- 填满但答案错误时不会误判完成。
- 简易模式只出现 1–4；高难模式只出现 1–9。

### 5.3 M2：题库生成与选题

任务：

1. 读取现有 4×4 JSONL，完成格式校验、唯一解校验与去重工具。（已完成）
2. 从现有 9×9 原始题库中固定种子抽样，解析并精简输出。（已完成）
3. 用独立求解器检查每道题的题面、值域和唯一解。（已完成）
4. 首发题库：100 道 4×4；四个 9×9 源文件各抽取 1,000 道，共 4,000 道。（已完成）
5. 实现本地洗牌袋与最近 20 题避重。（已完成）
6. 将来源、许可证说明和构建统计写入题库生成记录。（已完成）

交付物：精简运行时题库、题库构建脚本、校验报告。

验收标准：

- 运行时不执行大规模生成或求解搜索。
- 原始大体积题库不进入发布包。
- 任意发布题目的预置值与解一致且恰好有一个解。
- 同一轮题目不会无故连续重复。

### 5.4 M3：双模式存档与恢复

任务：

1. 为简易和高难模式分别保存一份 `GameState`。
2. 落子、清除、撤销后防抖保存；暂停、切换模式、页面隐藏和完成时立即保存。
3. 实现存档结构校验、版本号、逐版迁移和损坏回退。
4. 实现 localStorage 不可用或写满时的内存态降级。
5. 恢复时校验预置格不可变、数组长度、数值范围和题面一致性。

交付物：自动存档服务、恢复流程、迁移测试。

验收标准：

- 填入三步后重开页面，盘面、用时和撤销历史可恢复。
- 简易进行中切换高难，再切回简易，原局保持不变。
- 损坏存档不会导致白屏或无限报错。
- 存储失败时仍能在当前会话完成游戏，并显示未保存状态。

### 5.5 M4：角色素材与 BGM

#### 角色头像

1. 优化 9 张默认头像为适合棋盘显示的方形运行时资源。
2. 固定简易模式映射：1 洛天依、2 乐正绫、3 星尘、4 言和。
3. 实现 4 人版和 9 人版各自的上传、裁切、预览、排序及恢复默认。
4. 输出 256×256 WebP；编码失败时回退 JPEG 或 PNG。
5. 用户二进制资源写入 IndexedDB，元数据写入 localStorage。
6. 替换资源采用“写入新资源 → 更新元数据 → 删除旧资源”的事务顺序。

#### BGM

1. 准备获得授权且适合循环的内置短 BGM。
2. 实现播放、暂停、上一首、下一首、循环和音量记忆。
3. 首次播放必须由用户手势触发，并处理自动播放拒绝。
4. B站 Toy 在能力检测后开放用户音频导入。
5. 小红书端隐藏音频上传入口，只提供内置 BGM。
6. 对不可播放、超限、存储失败和页面隐藏提供明确降级。

交付物：头像管理弹层、媒体存储服务、BGM 播放器。

验收标准：

- 更换头像只改变显示，不改变题目数值和答案。
- 4 人与 9 人配置互不覆盖。
- 上传失败时保留原头像。
- 页面隐藏后音频暂停；切歌后旧 Blob URL 被释放。
- BGM 不可用时数独主流程仍能正常运行。

### 5.6 M5：双平台构建与适配

#### 共用任务

1. 所有发布资源使用 `./` 相对路径。
2. 禁止网络请求、外部 CDN、iframe、Worker、WASM 和动态代码执行。
3. 脚本使用经典外链，不使用内联脚本、行内事件或 `type="module"`。
4. 为安全区、窄屏、横屏和长文本提供基线样式。
5. 建立资源缺失、禁用 API、包体和入口结构自动检查。

#### B站 Toy 产物

- 输出 `dist/toy`。
- 验证 `/toy/<slug>/` 子路径下没有资源 404。
- 验证刷新、预览、音频和本地存储。
- 根据平台当前规则准备标题、封面、简介和审核说明。

#### 小红书小工具产物

- 输出 `dist/xhs`，ZIP 根目录直接包含 `index.html`。
- 确保文件类型、CSP、Chrome 61 兼容和端能力符合门禁。
- ZIP 不超过 10 MiB，体验目标尽量不超过 2 MiB。
- 头像可选择图片；不展示无效的音频文件选择入口。

交付物：两套独立发布目录、ZIP、审计结果和平台差异说明。

验收标准：

- 两个平台断网均可完成一局。
- 开发者工具或审计记录中没有业务网络请求。
- 小红书 ZIP 解压后不多套一层目录。
- 生产包不包含原始题库、源码映射、构建配置和临时文件。

### 5.7 M6：测试、验收与发布

任务：

1. 完成单元测试、集成测试、静态审计和视觉回归。
2. 在至少一台 Android 和一台 iOS 真机完成核心流程。
3. 验证 320 px 窄屏、常见手机纵屏、横屏和安全区设备。
4. 完成素材授权清单、隐私说明、版本说明和已知问题清单。
5. 先执行平台预览，再提交审核；保留可回退的上一稳定产物。

交付物：候选发布包、测试报告、发布记录、回滚包。

验收标准：P0 验收清单全部通过；未通过项必须有负责人、风险结论和明确的发布豁免，不允许口头跳过。

## 7. 任务优先级

### P0：首发必须完成

- 数独核心规则与唯一解题库。
- 4×4、9×9 模式切换。
- 双模式自动存档和异常恢复。
- 默认 4 人/9 人角色映射。
- 角色头像上传、裁切和恢复默认。
- 内置 BGM 基础播放控制。
- 双平台离线构建、兼容与体积门禁。
- 真机核心流程与素材授权检查。

### P1：首发后优先评估

- 候选笔记模式。
- 一步提示和错误原因说明。
- 局内成绩、最佳用时和本地统计。
- 更多内置头像主题和音乐主题。
- 分享成绩图片，但必须先确认平台能力和素材授权。

### 暂不规划

- 在线排行、账号、云同步、联网曲库、联机对战、广告和支付。

## 8. 测试与质量门禁

### 8.1 合并前

- 新增领域逻辑必须有单元测试。
- 修复缺陷必须补充可复现测试或明确的人工回归步骤。
- 不得引入外部运行时资源和被平台禁止的能力。
- 界面变化必须附 4×4、9×9 手机截图。

### 8.2 候选发布前

- 数独题目格式、唯一解、映射和完成判断全部通过。
- 自动存档、损坏恢复、存储失败降级全部通过。
- 头像上传失败、音频不可播放和页面隐藏场景全部通过。
- 全量资源引用存在，无 404、无绝对路径、无外部请求。
- 两套构建包分别审计，不用一个平台通过代替另一个平台通过。
- 未完成 Chrome 61 或真机测试时，必须明确标记“未实测”，不能写成“已兼容”。

### 8.3 发布后

- 记录版本号、构建时间、提交标识、包体和平台审核结果。
- 检查首日白屏、资源 404、存档失败和媒体失败反馈。
- 严重问题优先回退到上一稳定包，再分析修复。

## 9. 风险与应对

| 风险 | 影响 | 预防与应对 |
| --- | --- | --- |
| 角色或 BGM 授权不清 | 无法发布或被下架 | M4 前建立授权清单；未确认素材不进入候选包 |
| 原始题库过大 | 包体超限、启动变慢 | 构建期抽样、校验和精简，原始文件不入包 |
| 用户图片或音频占满存储 | 保存失败 | 设置单文件和数量上限，提供删除与恢复默认 |
| 两个平台能力不同 | 功能入口无效 | 统一能力接口；小红书明确关闭音频导入 |
| Chrome 61 CSS/JS 不兼容 | 小红书旧设备白屏或错位 | ES2017 构建目标、基线 CSS、静态扫描与真机验证 |
| 自动存档损坏 | 用户进度丢失 | schemaVersion、读入校验、迁移和新局回退 |
| 音频显著增加包体 | 超过体验目标 | 使用短循环、低码率、减少曲目；优先保证游戏资源 |
| UI 动效影响低端机 | 操作卡顿 | 只用轻量 transform/opacity；页面隐藏时暂停 |
| 需求扩张 | 首发延期 | 严格执行 P0/P1 边界，新增功能先评估关键路径 |

## 10. 工作项管理规则

每个开发任务至少包含：

- 目标：用户最终能做什么。
- 范围：本任务负责和不负责的内容。
- 依赖：必须先完成的模块或待确认素材。
- 验收：可观察、可测试的完成条件。
- 平台差异：Toy 与小红书是否一致。
- 测试证据：自动化结果、截图或真机记录。

建议状态：`待梳理 → 可开发 → 开发中 → 待验证 → 已完成`。需求不清、素材未授权或平台能力未确认时，不能进入“可开发”。

## 11. 完成定义（Definition of Done）

一个功能只有同时满足以下条件才算完成：

1. 功能按验收标准运行，错误路径有明确反馈。
2. 领域逻辑与平台代码职责分离，没有把角色图片当作数独数值。
3. 自动化测试通过，必要的人工回归已记录。
4. 断网可用，资源路径和受限能力检查通过。
5. 4×4 与 9×9 均确认没有回归。
6. 双平台差异已实现或在界面中正确降级。
7. 文档、版本说明和已知限制同步更新。
