# M2：4×4 题库接入与测试说明

> 文档版本：v0.1  
> 完成日期：2026-10-04  
> 范围：M2 的 4×4 题库部分；9×9 题库见 `07_M2_9x9题库处理说明.md`

## 1. 数据来源与格式

本次读取项目根目录的 `grid-4_diff-25_placeholder-__enforce-non_unique.jsonl`。文件每行是一道独立题目，包含：

- `puzzle`：4×4 二维数组，空格以字符串 `"*"` 表示。
- `config.grid_size`：固定为 `4`。
- `config.difficulty`：当前数据为 `25`。
- `config.enforce_unique`：源数据声明为 `false`。
- `config.placeholder`：固定为 `"*"`。

源数据的 `enforce_unique: false` 只表示生成时未要求唯一解，不能据此认定题目有多解。因此构建脚本会独立求解并统计解的数量，不直接信任该字段。

## 2. 构建与校验流程

`scripts/build-4x4-bank.mjs` 按以下顺序处理题库：

1. 逐行解析 JSONL，并检查对象、棋盘尺寸、行宽、值域和占位符。
2. 将 `"*"` 转换为运行时使用的数字 `0`。
3. 检查题面中的预置值是否已经违反行、列或 2×2 宫规则。
4. 使用独立回溯求解器搜索，最多找到两个解即停止。
5. 仅接收恰好有一个解的题目；无解和多解题目均拒绝。
6. 按题面去重，并验证预置值与求得的完整答案一致。
7. 生成经典脚本 `puzzle-bank-4x4.js` 和统计报告 `data/reports/4x4-bank-report.json`。

运行时不会解析原始 JSONL，也不会执行大规模求解。页面只读取已校验、体积较小的 `puzzle-bank-4x4.js`，以适配离线运行和小红书小工具的资源约束。

## 3. 本次数据结果

| 指标 | 结果 |
| --- | ---: |
| JSONL 记录数 | 100 |
| 格式或值域不合法 | 0 |
| 重复题面 | 0 |
| 无解题 | 0 |
| 多解题 | 0 |
| 唯一解并接收 | 100 |
| 源数据声明 `enforce_unique: false` | 100 |
| 预置数字范围 | 12–14 个 |

结论：虽然全部记录都声明 `enforce_unique: false`，但独立求解器实际确认这 100 道题全部恰好有一个解，可作为当前 4×4 运行时题库。

## 4. 页面选题行为

- 简易模式首次开局直接从该题库取题。
- 点击“新一局”时使用本地洗牌袋取下一题，同一轮遍历完 100 题后才重新洗牌。
- 洗牌边界会避免与上一题立即重复。
- 9×9 模式现已按 easy、medium、hard、diabolical 四个源文件分别接入 1,000 道，共 4,000 道，具体处理过程见 `07_M2_9x9题库处理说明.md`。

## 5. 测试结果

- Node 自动化测试：12 项全部通过。
- 题库专项测试：重新求解全部 100 道题，并逐题核对生成答案。
- 浏览器交互冒烟：通过新局换题、正确填入、冲突提示、清除、撤销、自动完成和模式切换。
- Toy 与小红书构建：均仅复制发布白名单文件，原始 JSONL 不进入发布目录。
- 当前两套未压缩发布目录均约为 1.10 MiB。

## 6. 使用命令

```text
npm run bank:4x4
npm test
npm run check
```

其中 `npm test` 和 `npm run build` 都会先重新生成并校验 4×4 运行时题库，避免源数据变化后仍使用过期产物。
