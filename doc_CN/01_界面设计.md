# 虚拟歌手数独——界面设计文档

> 文档版本：v0.1  
> 设计状态：开发基线  
> 最后更新：2026-10-03

## 1. 设计目标

本产品是一款以虚拟歌手角色图标替代数字的移动端数独游戏，同时发布到 B站 Toy 与小红书小工具。界面设计需同时满足：

1. 玩家能在 3 秒内理解“角色图标就是数字”。
2. 4×4 与 9×9 共用一套交互，模式切换不改变基本操作习惯。
3. 以 `#66CCFF` 为第一主色，其他强调色使用 `66`、`CC`、`FF` 的 RGB 排列组合。
4. 9×9 在窄屏手机上仍能看清角色、选中状态和宫格边界。
5. 图标、BGM 和游戏进度都能在离线环境中工作。
6. 平台不支持的能力必须明确隐藏或解释，不出现无响应按钮。

## 2. 关键产品约定

| 界面名称 | 棋盘 | 角色数 | 默认辅助 | 题目来源 |
| --- | ---: | ---: | --- | --- |
| 简易模式 | 4×4，2×2 宫 | 4 | 同行同列高亮、冲突提示、剩余数提示 | 构建期生成并校验的 4×4 题库 |
| 高难模式 | 9×9，3×3 宫 | 9 | 选中高亮；冲突提示可关闭；简单/中等/困难/魔鬼四档切换 | 仓库四个 9×9 源文件各自的构建期精选子集 |

- 角色与数值采用固定映射：本局中的“角色 1”始终代表数值 1，不因位置或剩余数量改变。
- 盘面主要显示角色头像，不直接用大号阿拉伯数字替代角色。
- 为降低首次学习成本，角色选择按钮可显示小号 `1–4` 或 `1–9` 角标；角标可在设置中关闭，读屏标签始终保留。
- 简易和高难模式分别保留一份未完成存档。点击底部模式开关时先保存当前局，再恢复目标模式的上次进度。

## 3. 视觉语言

### 3.1 色彩系统

主色及辅助强调色限定为 `66`、`CC`、`FF` 三组通道值的排列；大面积背景使用主色的透明叠加或与白色混合，避免高饱和色铺满页面。

| 角色 | 色值 | 用途 |
| --- | --- | --- |
| 第一主色 / 天空蓝 | `#66CCFF` | 品牌、主按钮、选中边框、进度条 |
| 薄荷青 | `#66FFCC` | 正确、完成、保存成功 |
| 紫罗兰 | `#CC66FF` | 高难模式、次级强调 |
| 青柠 | `#CCFF66` | 提示、剩余数量 |
| 樱粉 | `#FF66CC` | 冲突、错误、危险操作 |
| 琥珀黄 | `#FFCC66` | BGM、计时、提醒 |

为保证文字对比度，允许使用必要的中性色：

- 主文字：`#16324A`
- 次文字：`#49677F`
- 页面底色：`#F7FCFF`
- 卡片：`#FFFFFF`
- 分隔线：`rgba(22, 50, 74, 0.14)`
- 禁用态：`rgba(73, 103, 127, 0.38)`

使用规则：

- `#66CCFF` 负责品牌识别，不同时承担成功、警告和错误语义。
- 错误状态除樱粉色外必须配合“!”角标、抖动一次或文字提示，不能只靠颜色。
- 高难模式使用 `#CC66FF` 作为模式标识，但棋盘核心操作仍保持主色一致。
- 透明背景应预先提供不依赖毛玻璃的实色回退。

### 3.2 背景图案

主界面背景使用 `assets/music-note-background.svg`，视觉母题为“经典音符 + 圆形节拍”：

- 音符主体统一使用第一主色 `#66CCFF`，包含八分音符、连音符和轻量五线谱。
- 音符采用约 10%–30% 的透明度，只用于建立音乐主题，不与棋盘、角色图标或正文争夺注意力。
- 保留原有圆形图案，以 `#66FFCC`、`#CC66FF`、`#FF66CC`、`#FFCC66`、`#CCFF66` 作低透明度点缀。
- 圆形与音符应疏密错落，内容卡片区域保持足够留白；不能把高饱和图案直接铺在正文下方。
- SVG 必须随离线包提供并使用相对路径引用，不使用外部图片、字体或滤镜依赖。
- 桌面外围背景可纵向重复；应用壳内部仅显示一次，以免小屏出现过密纹理。

V2 按 Canva 概念稿进一步收敛：较大的音符、五线谱和圆形集中在画面边缘，棋盘与信息卡所在的中央区域保持高留白；顶部加入 `NOTE V2` 小标签，便于与第一版视觉稿区分。

简易模式的四位角色固定按文件名前缀映射，不自动重排：

| 数值 | 文件 | 角色 |
| --- | --- | --- |
| 1 | `1洛天依.png` | 洛天依 |
| 2 | `2乐正绫.png` | 乐正绫 |
| 3 | `3星尘.jpg` | 星尘 |
| 4 | `4言和.png` | 言和 |

### 3.3 字体与图标

- 字体使用系统字体栈，不随包携带非必要字体文件。
- 页面标题：20 px / 600；区块标题：16 px / 600；正文：14 px / 400；辅助信息：12 px / 400。
- 功能图标采用简洁线性 SVG，并配文字或可访问名称；关键操作不只显示无含义的图形。
- 角色图标使用圆角方形头像框，圆角为单元格宽度的 18%–22%，比圆形裁切保留更多发型和服装特征。

### 3.4 空间与圆角

- 基础间距单位：4 px。
- 页面左右安全边距：12 px；宽屏内容最大宽度：560 px。
- 卡片圆角：16 px；普通按钮：12 px；底部弹层顶部圆角：20 px。
- 选择器按钮触控区域目标为 44×44 px 以上。9×9 棋盘格受屏宽限制时可小于 44 px，但必须使用完整方格作为触控区，并提供清晰的行列高亮反馈。

## 4. 信息架构

应用采用单页结构，避免跨页面跳转：

```text
游戏主界面
├─ 顶部栏
│  ├─ 游戏标题 / 模式标签
│  ├─ 计时与错误数
│  └─ BGM、暂停、更多
├─ 状态提示条
├─ 数独棋盘（4×4 或 9×9）
│  └─ 9×9 难度选择（简单 easy / 中等 medium / 困难 hard / 魔鬼 diabolical）
├─ 角色填入选择器（4 个或 9 个）
├─ 操作工具条（撤销、清除、新局）
└─ 底部模式切换（简易 4×4 / 高难 9×9）

底部弹层
├─ 角色图标自定义
├─ BGM 曲目与导入
├─ 游戏设置
└─ 新局确认 / 完成结果
```

“角色图标自定义”和“BGM”不另开 HTML 页面，均使用页内底部弹层或全屏弹层。

## 5. 游戏主界面

### 5.1 纵向手机布局

```text
┌──────────────────────────────┐
│ 虚拟歌手数独  [简易]  02:18 │  顶部栏
│                       ♫ Ⅱ ⋯ │
├──────────────────────────────┤
│ 已自动恢复上次进度 / 操作提示 │  状态提示条
├──────────────────────────────┤
│  ┌────── 数独棋盘 ──────┐   │
│  │ 角色头像组成的 4×4/9×9 │   │
│  └──────────────────────┘   │
├──────────────────────────────┤
│ [角色1][角色2][角色3] ...    │  填入选择器
│  剩余3   剩余5   已用完       │
├──────────────────────────────┤
│   ↶ 撤销      ⌫ 清除    ＋新局 │  工具条
├──────────────────────────────┤
│ [ 简易 · 4×4 ] [ 高难 · 9×9 ]│  固定底栏
└──────────────────────────────┘
          含底部安全区
```

布局规则：

- 棋盘宽度为 `min(100vw - 24px, 540px)`，保持正方形。
- 页面高度不足时，中间内容可纵向滚动，底部模式切换保持可见；不得让底栏遮住角色选择器。
- 360–599 px 宽度使用单列布局。
- 600 px 以上或横屏时，棋盘居左，选择器与工具区居右；整体仍限制在适合触控的宽度内。
- 顶部栏和底栏应用安全区变量，兼容刘海屏及容器模拟安全区。

### 5.2 顶部栏

顶部栏包含：

- 产品名“虚拟歌手数独”；
- 当前模式胶囊标签“简易 4×4”或“高难 9×9”；
- 计时，暂停时停止；
- BGM 入口，图标旁用小动效表示正在播放；
- 暂停按钮；
- 更多菜单，包含图标自定义、设置、玩法说明。

窄屏时产品名可缩短为“歌手数独”，计时与操作按钮不得被省略。

### 5.3 状态提示条

状态提示条只在需要时出现，高度固定，避免棋盘上下跳动：

- 恢复存档：“已恢复上次进度”；
- 首次引导：“先点空格，再选择一位角色”；
- 冲突：“这个角色已在同一行、列或宫中”；
- 保存失败：“本次进度暂未保存，请检查存储空间”；
- 平台限制：“当前平台仅支持内置 BGM”。

普通提示 2 秒后淡出；错误提示需保留到下一次有效操作或用户关闭。

## 6. 数独棋盘

### 6.1 结构

- 4×4 使用 2×2 宫；第 2 行和第 2 列之后显示 2 px 宫界线。
- 9×9 使用 3×3 宫；第 3、6 行和第 3、6 列之后显示 2 px 宫界线。
- 普通格线为 1 px，宫界线使用主文字色或主色的高不透明度版本。
- 每个格子使用原生 `button` 语义；预置格不可编辑，但仍可聚焦和选中以查看关联格。

### 6.2 单元格状态

| 状态 | 视觉表现 | 交互 |
| --- | --- | --- |
| 空白 | 白底、浅色格线 | 可选择 |
| 题目预置 | 角色图标 100% 不透明、浅蓝底、左上锁定点 | 不可覆盖 |
| 玩家填入 | 角色图标 92% 不透明、白底 | 可清除、可撤销 |
| 当前选中 | `#66CCFF` 3 px 内边框 | 等待填入 |
| 同行 / 同列 / 同宫 | `rgba(102, 204, 255, 0.12)` 背景 | 无额外操作 |
| 同角色 | 薄荷色底纹 + 小圆点 | 帮助追踪相同值 |
| 冲突 | `#FF66CC` 边框 + “!”角标 + 单次轻微抖动 | 简易模式默认即时显示 |
| 已完成 | 棋盘外框切换为薄荷色，依次点亮格子 | 打开结算弹层 |

角色图片应预处理为正方形缩略图；格内使用 `object-fit: cover`。如果图片缺失或解码失败，用该角色的色块、编号和名称首字作为容错占位，不得显示破图图标。

### 6.3 输入流程

默认采用“先选格，再选角色”：

1. 点击空格，棋盘高亮当前格及关联区域。
2. 点击下方角色按钮，将对应数值填入当前格。
3. 填入后保持当前格选中，便于撤销或清除；不自动跳格，避免误操作。
4. 点击已填格后点击另一角色，可直接替换并生成一条撤销记录。
5. 点击预置格只做高亮，不允许修改。

可在设置中开启“先选角色，再连续填格”，但不作为首发默认交互。

### 6.4 完成反馈

完成校验通过后：

- 停止计时并立即保存完成状态；
- 角色格以 60–90 ms 间隔轻微上浮，动画总时长不超过 1 秒；
- 打开结果弹层，展示模式、用时、错误数；
- 提供“再来一局”和“返回棋盘”两个操作；
- 动效关闭或系统偏好减少动态效果时，改用静态完成边框。

## 7. 角色填入选择器

### 7.1 简易模式

- 4 个角色按钮优先单行等宽显示。
- 每个按钮包含头像、可选数字角标和剩余可填数量。
- 对应角色已全部正确放置时，按钮降低饱和度并显示对勾，但仍可点击用于高亮同角色格。

### 7.2 高难模式

- 9 个角色在手机上采用 5+4 或 3×3 布局，以实际屏宽选择不拥挤的方案。
- 不使用横向滚动，确保所有候选角色始终可见。
- 按钮间距使用 margin 作为兼容基线，不依赖 Flex `gap`。

## 8. 角色图标自定义

### 8.1 入口与结构

从“更多 → 角色图标”进入全屏弹层：

```text
角色图标
[4人版] [9人版]

[1 头像] [2 头像] [3 头像] ...
 点击任一槽位：上传 / 裁切 / 替换 / 恢复默认

[恢复本组默认]                   [应用]
```

- 4 人版和 9 人版是两套独立配置。
- 首次进入 9 人版时可继承 4 人版的前 4 个槽位，其余槽位由内置角色补齐。
- 当前 `公式服头像` 目录已提供 9 张方形角色头像，可直接构成 9 人默认预设；发布前仍需逐张确认授权状态与小尺寸辨识度。

### 8.2 上传与裁切

上传流程：

1. 用户点击明确的“上传图片”按钮后调起系统选择器。
2. 仅接受 PNG、JPEG、WebP；源文件建议限制在 5 MiB 内。
3. 在本地弹层内完成正方形裁切、缩放和位置调整。
4. 导出 256×256 缩略图；优先 WebP，兼容性不足时使用 JPEG/PNG。
5. 写入本地素材存储并立即预览；点击“应用”后更新角色映射。

校验与提示：

- 透明图应提供浅色棋盘背景预览，避免白色角色边缘消失。
- 同一文件重复用于多个槽位时给出“辨识度可能不足”的警告，但不强制阻止。
- 图片读取、裁切或保存失败时保留原图标，不提交半成品配置。
- 每个槽位提供角色名称文本，名称仅作辅助，不影响数独数值。

## 9. BGM 设计

### 9.1 快捷控制

点击顶部音乐按钮打开底部弹层：

```text
正在播放：曲目名称
[上一首] [播放/暂停] [下一首]
音量 ─────────○

内置曲目列表
自定义曲目列表
[＋导入本地 BGM]
```

- 首次进入默认静音；只有用户发生点击后才开始播放，遵守浏览器自动播放限制。
- 曲目切换使用 200–300 ms 音量淡出/淡入，避免爆音。
- 页面隐藏或游戏暂停时默认暂停，恢复页面后不自动播放，除非用户设置了“恢复时继续”。
- 播放状态、音量和上次曲目写入偏好设置，但媒体解码失败不能影响游戏。

### 9.2 自定义 BGM

- B站 Toy / 普通浏览器：显示“导入本地 BGM”，通过文件选择器读取可播放音频；建议单文件不超过 8 MiB，只保存已验证可播放的文件。
- 小红书小工具：文件选择器仅支持图片和视频，不支持音频导入，因此隐藏上传按钮，并显示“当前平台仅支持内置 BGM”。
- 不做联网曲库、URL 导入或音频转码。
- 自定义音频仅存本机，清理应用数据后可能丢失。

## 10. 底部模式切换

固定底栏使用双段式控件：

- 左侧：`简易 · 4×4`，选中态使用 `#66CCFF`。
- 右侧：`高难 · 9×9`，选中态使用 `#CC66FF`。

切换规则：

1. 立即保存当前模式进度。
2. 若目标模式有未完成存档，直接恢复并提示“已恢复高难/简易进度”。
3. 若无存档，生成或抽取新题。
4. 模式切换不删除任何进度，也不弹破坏性确认框。
5. “新局”才会替换当前模式存档，并在已有进度时二次确认。

## 11. 暂停、恢复与异常状态

### 11.1 暂停层

暂停后使用不透明卡片遮住棋盘内容，防止计时停止时继续观察。提供：

- 继续游戏；
- 重新开始本局；
- 返回设置。

### 11.2 自动恢复

应用启动时：

- 存在有效未完成存档：自动恢复，并显示一次轻提示。
- 上次存档已完成：进入完成棋盘，用户可查看结果或新开一局。
- 存档损坏或版本不兼容：保留可读的用户图标/BGM设置，放弃损坏棋局并提示“旧进度无法恢复，已为你开启新局”。

### 11.3 空状态和失败状态

- 9 人角色未配置完整：禁止开始高难新局，直接定位缺失槽位。
- 题库加载失败：显示重试和返回简易模式，不白屏。
- 本地存储不可用：允许临时游玩，同时常驻提示本次进度不会保存。
- BGM 加载失败：自动静音并允许删除该曲目，不中断游戏。

## 12. 响应式与跨端规则

- 使用百分比、Flexbox 和基础 Grid，不写死单一设备宽度。
- 最低兼容基线按 Android 8.1 / Chrome WebView 61 设计；`clamp()`、`aspect-ratio`、Flex `gap`、动态视口单位等不可作为唯一实现。
- `viewport` 必须包含 `viewport-fit=cover`，安全区使用容器变量与 `env()` 双回退。
- 关键操作默认可见，不依赖鼠标悬停。
- Pointer Events 统一鼠标和触摸；必要时提供 touch 事件回退。
- 键盘、横竖屏或容器高度变化时重新计算可视高度，但不重置棋局或棋盘选中状态。

## 13. 可访问性

- 棋盘使用 `role="grid"`，格子使用 `role="gridcell"` 或等价原生按钮结构。
- 每格读屏名称包含行、列、状态和角色名，例如“第 2 行第 3 列，玩家填入，角色 5”。
- 角色选择器按钮同时包含角色名、代表数值和剩余数量。
- 所有文字与背景达到可读对比度；装饰色板不影响主文字中性色选择。
- 支持 `prefers-reduced-motion`，关闭抖动、连锁点亮和非必要循环动画。
- 错误、选中、锁定、完成等状态不能只依赖色相区别。

## 14. 素材规范

### 14.1 内置角色图

- 运行时默认头像位于 `公式服头像`，均为接近正方形的缩略图；后续如保留更大源图，不应把未经优化的原图打入运行包。
- 建议输出 256×256 WebP，单张目标 20–60 KiB；必要时同时提供 JPEG/PNG 回退。
- 9 个角色应在发色、轮廓和背景色上有明显区别，不能只靠细小服装差异识别。
- 现有 9 张默认头像仍需在 4×4 与 9×9 的实际格子尺寸下逐张检查焦点和辨识度。

### 14.2 权利与审核

- 发布前确认内置角色图、角色名称和 BGM 的版权、商用授权及平台发布权限。
- 用户上传素材只保存在本地；界面需提示用户仅上传有权使用的图片和音频。
- 不把用户上传文件写入仓库或随发布包重新分发。
