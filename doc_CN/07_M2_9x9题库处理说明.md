# M2：9×9 题库处理与读取说明

> 文档版本：v0.1  
> 完成日期：2026-10-04  
> 数据来源：`sudoku-exchange-puzzle-bank`

## 1. 数据库结构

本地数据库包含 `easy.txt`、`medium.txt`、`hard.txt` 和 `diabolical.txt`。每行是一道 9×9 数独，以三个空白分隔字段表示：

1. 12 位十六进制哈希，用于随机化记录顺序。
2. 81 位题面数字，其中 `0` 代表空格。
3. Sukaku Explainer 难度评分。

本项目高难模式使用：

| 文件 | 原始记录数 | 难度评分 | 构建选取数 |
| --- | ---: | --- | ---: |
| `easy.txt` | 100,000 | < 1.5 | 1,000 |
| `medium.txt` | 352,643 | 1.5–2.4 | 1,000 |
| `hard.txt` | 321,592 | 2.5–4.9 | 1,000 |
| `diabolical.txt` | 119,681 | ≥ 5.0 | 1,000 |

数据集 README 声明题目由 QQWing 生成并保证唯一解，数据集以 Unlicense 献给公共领域。本项目仍执行独立验证，不把来源声明当作唯一的质量门禁。

## 2. 完整源库直接读取

`scripts/exchange-puzzle-repository.mjs` 是完整源库的统一访问层。它遵循原仓库的固定记录格式，不建立冗余数据库副本：

1. 初始化时读取每个文件开头的一小段，自动识别 LF 的 100 字节记录或 CRLF 的 101 字节记录。
2. 通过文件大小除以记录长度得到真实题数。
3. 按 `偏移量 = 零基题号 × 记录长度` 定位题目，只读取一条记录。
4. 把“哈希、81 位题面、评分”转换为统一题目对象。
5. 同时提供逐行流式接口，发布构建与完整源库读取共用同一解析规则。

因此完整 893,916 道题在开发和构建环境中都可访问，读取末尾题目不需要先扫描前面的记录。命令行使用一基题号：

```text
npm run bank:read -- --info
npm run bank:read -- easy 1
npm run bank:read -- medium 352643
npm run bank:read -- hard 321592
npm run bank:read -- diabolical 119681
```

读取单题时会同时运行独立求解器并输出完整答案。代码接口 `ExchangePuzzleRepository.read(difficulty, zeroBasedIndex)` 使用零基题号。

## 3. 平台发布构建

`scripts/build-9x9-bank.mjs` 通过上述仓库的流式接口读取，避免一次性把约 90 MiB 的四个源文件全部载入内存。处理流程为：

1. 校验每行的哈希、81 位题面和评分字段；题目难度直接由所在源文件决定，不根据评分重新归类。
2. 四档分别以固定种子 `0x66ccff01`、`0x66ccff05`、`0x66ccff09` 和 `0xcc66ff09` 执行蓄水池抽样。
3. 对入选题面去重。
4. 使用项目自己的 9×9 位掩码回溯求解器搜索，最多发现两个解。
5. 仅允许恰好有一个解的题目进入运行时题库。
6. 将每题压缩为“哈希、81 位题面、81 位答案、评分”四字段数组，再写出 `puzzle-bank-9x9.js` 与 `data/reports/9x9-bank-report.json`。

固定种子与固定源文件能让每次构建得到完全相同的 4,000 道题。生成结构保留四个独立题库及各自的源文件名，不再先合并后重新分组。源数据库不会复制到发布目录，运行时只在抽到某题时把两段数字字符串展开为数组，不执行求解。

## 5. 游戏内读取方式

- 页面通过经典脚本 `puzzle-bank-9x9.js` 读取 `window.VocalSudokuPuzzleBank9`。
- 9×9 模式提供“简单、中等、困难、魔鬼”四个可见按钮，并直接显示对应的 `easy.txt`、`medium.txt`、`hard.txt`、`diabolical.txt`。
- 切换难度会立即从对应源文件的精简题库开始新题，提示区同时显示中文难度、源文件名与题量。
- 四档各自维护独立洗牌袋，一轮内不会重复。
- 每档洗牌袋重新装填时，最近 20 道题被放到队尾，避免跨轮短期重复。

## 6. 测试与发布结果

- Node 自动化测试：19 项全部通过。
- 完整源库专项测试：验证四个文件的真实题数、固定记录长度、首条/末条随机访问、越界保护和唯一解。
- 真实浏览器冒烟：确认 4×4 与 9×9 均能“新一局”换题，四档按钮能切换到对应题库。
- Toy 与小红书发布包只包含约 738 KiB 的紧凑 9×9 运行时题库。
- 四个原始 `.txt` 和整个数据库目录均不进入发布包。
- Chrome 61 / Android 8.1、平台模拟器和真机兼容性仍未实测。

## 7. 使用命令

```text
npm run bank:9x9
npm run bank
npm run bank:read -- --info
npm run bank:read -- hard 321592
npm test
npm run check
```

`npm test` 与 `npm run build` 都会先重新构建两套题库，源文件缺失、格式异常、数量不足或唯一解验证失败都会直接阻止构建。
